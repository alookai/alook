# Image pipeline and diagnostic contract

This audit describes the source paths and the observations needed to distinguish a slow request, decode failure, a readiness timeout and node retirement. It does not change image presentation, retries, authorization, cache policy or cancellation ownership. A source mechanism is not attribution of an earlier production failure.

## Events and interpretation

- Join by session + page_instance_id + telemetry_generation, then image_instance_id/node_id/source_id and attempt/image_generation. Identifiers are opaque; source mapping is bounded to 512 entries and is cleared on telemetry retirement. Only image candidates/registered sources allocate resource source ids. correlation_evictions and correlation_size explicitly identify lost join capability after eviction; an id change across this boundary does not establish a src change. Eviction can break a long-distance source join; identical URLs never imply identical nodes. Data URLs longer than 4096 characters deliberately have no source id; join their node/session stages instead.
- Hook events report attach/detach, effect setup/cleanup, eligibility, timer start/clear, timeout, load/error, decode start/ready/error, retry and state/ignored. `current_node=false` describes an old node; ignored_reason distinguishes inactive owner, generation, attempt and existing terminal state. decode_supported/decode_called distinguish API availability and invocation. Without the API, decode_unavailable and pixels_ready report the dimension fallback; image_failure separates decode rejection, no pixels, load error and abort. Existing same-component old-node acceptance is observed, not repaired.
- DOM observations are asynchronous mutation snapshots. A ref detach can precede physical DOM removal; connected is sampled at event time. A snapshot of a complete image is not an observed historical load/decode. The observer never invokes decode or changes image state.
- Each Resource Timing entry has an opaque resource_id distinct from the API request_id. Resource Timing reports fetchStart/requestStart/responseStart/responseEnd, status when available, deliveryType when exposed, bytes and actual timeOrigin. Zero timings/status/transfer do not assert success, error or cache hit. Multiple same-source requests remain multiple candidates; the browser API supplies no request id joining an img to one RT entry. Cross-origin timing restrictions and memory-cache omissions remain explicit capability limits.
- `image.operation` carries only enumerated operation/key, opaque target id, sequence and clock. The observer excludes global class/style mutation tracking. Image lifecycle/operation observations share a live budget of 200 events per second, with telemetry.drop/image_rate_limit reporting omitted events before fields are allocated. Scroll/pointer-over events are throttled to 100 ms; absence of an operation event is not proof no operation occurred. No key text, DOM label, filename, alt, message id/body or full private URL is recorded.
- `request.boundary` marks an owner deadline start/abort before an API may begin. `request.abort` preserves the API request id and exact observed signal fields. `query.boundary` records native Query observer counts and signal abort. `query_signal` identifies signal ownership; pair the actual last-observer event or explicit account_cancel to attribute the initiator. Unknown callers stay unknown. Caller-supplied abort reason objects are not logged.
- View/read controllers bind telemetry generation at creation; unknown controller ownership does not emit a boundary in a replacement session. Query owners bind at their first observed lifecycle and renew on a fresh observed Query signal. Retired owner boundaries are suppressed, so missing boundaries remain an explicit observation gap. Existing cancellation sites distinguish conversation deadline/parent signal, view layout cleanup versus explicit retire, account Query cancellation, read supersession and share deadline/cleanup. No signal is replaced for instrumentation; original reasons, timing and Query cancellation semantics remain intact.

## Consent, delivery and original WebView diagnosis

Events use the existing eligibility, schema cleaning, queue, sink, Faro beforeSend and transport. Consent withdrawal, account replacement, pagehide and session retirement clear queued observations and source correlation. Late decode/preparation observations from the old telemetry generation are discarded. Early queue overflow is reported by telemetry.drop when an eligible sink becomes available; an event call is not proof of Collector ingestion.

1. Keep the original WebView window and failure node. Record installed binary/version/configuration separately and the current loaded web release; do not open Chrome or reload as a substitute for that instance.
2. Verify ordinary analytics consent and valid public Collector configuration on that build. With consent granted, bind new image events to the actual page/session/environment/release and WebView hint. A release label is useful only when its compiled source and received payload are also checked.
3. If collection is disabled or delivery unavailable, use the system Web Inspector on the same existing WebView, when that installed binary is inspectable: current img/src/currentSrc/state/natural dimensions, original Network response/redirect/cache receipt and performance timeOrigin. Keep private URLs/headers within the authorized audience; share safe equality flags and clock/dimension readings.
4. If Safari Develop cannot discover that installed WebView, native inspector capability is unavailable. Neither a screenshot nor a different browser instance can recover its past attach/load/decode/request sequence. Ordinary consent changes can enable later observations on the same page; they cannot reconstruct earlier events. Preserve this gap rather than changing native permissions or bypassing consent.
5. Reproduce using normal product operations under the assigned QA owner. Match error/timeout/decode and node lifetime within one page/session, then compare resource and API cancellation evidence separately. Earlier observations with falling startTime but no recorded timeOrigin cannot be fused into the same attempt.

## Regression obligations

The repository DOM harness exercises actual React ref/parent replacement, deferred decode, timer and Retry behavior. Browser tests exercise actual DOM mutation/load/error and safe RT joins; Query tests use real QueryObserver subscription and consumed signals. Real Faro tests inspect cleaned transport payloads and consent/session boundaries. Existing route, conversion, upload, SW and image/lightbox suites remain required. These controlled tests establish the diagnostic contract; independent live WebView/HTTP/cache/OS journeys require their own source-bound evidence.
