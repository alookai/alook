**To share a Claude Code session, send a session link for cloud work or run `/export` in the local CLI.** If your teammate is taking over the task, include the working files, current state, and next action too. A chat transcript on its own does not give someone your local setup or uncommitted code.

Say you have been updating a signup flow in Claude Code, and a teammate asks why you added an email check. If they just want the reasoning, send them the conversation. If they are picking up the remaining work, include the code and spell out what is still unfinished.

Before changing link permissions or exporting files, figure out whether your teammate is simply reading along or taking over the work. When someone is picking up an unfinished task, start with the handoff steps below.

## Choose what to share from Claude Code

For a quick decision review, the conversation log is usually enough. Someone writing the next patch will need the working files too. Match what you send to the job:

If you just want to control your own local session from your phone or another browser, use [Claude Code Remote Control](https://code.claude.com/docs/en/remote-control) instead. Claude stays running on your original computer, which must stay online with the process open. That is built for remote access by you, not handing a task to a teammate.

[Cross-session messaging](https://code.claude.com/docs/en/cross-session-messaging) lets Claude pass text notes between sessions, without copying the sender's full chat history or project files.

### Share work from Claude Code Desktop

In the [Desktop app](https://code.claude.com/docs/en/desktop), cloud sessions use the link-sharing steps below. For a local session, ask Claude to save a handoff note inside the project folder so it travels alongside the files your teammate needs. You can jump straight to those files from the menu next to the session title (**Open in** → your file manager), check the note, and send everything together.

## How do I hand off a coding agent session to a teammate?

**Send the current code revision, any uncommitted changes, and a short note covering what is done and what needs to happen next.** Include the reasoning behind decisions your teammate needs to review, plus which checks you actually ran. If they also want to read the original discussion, attach a cloud-session link or CLI `/export` file. Your teammate then opens the shared work in their own workspace and verifies it against your note before editing.

For the signup example, a solid handoff note looks like this:

```text
Task: Finish the signup email check.
Code: Open the linked draft PR and
confirm its current revision.
Done: The form displays the
email-check result.
Open: Decide what happens when the
check service times out.
Checks: See the attached test log;
confirm it matches the revision.
Next: Review the timeout behavior
before changing the UI.
Decision needed: Product owner
approves the user-facing behavior.
```

Swap in the actual state of your branch. Include any local edits that are not pushed to the linked revision yet, and be upfront if you have not run tests.

On the receiving end, your teammate can pick up the signup work in four steps:

1. Open the linked code revision and any shared unfinished changes, then compare them against the note and confirm which commit the test log covers.
2. Ask their coding agent to inspect the files and summarize the current state. For this example, they can run:

```text
Read the handoff note and inspect
the linked code revision and shared
unfinished changes. Tell me what is
done, what remains unresolved, and
which checks actually ran. Identify
any mismatch between the note and
the files. Propose the first action
for finishing the signup timeout
behavior and which test should pass.
Wait for me to resolve the product
decision before implementing it.
```

3. Settle the timeout behavior with the product owner, then ask the agent to implement the agreed change.
4. Test the updated timeout path against the agreed behavior, and record the commit and actual test result.

Because the handoff lives in files and commits, your teammate does not need the same account or harness. Someone on another Claude login or on Codex can drop the shared code and handoff note straight into their own setup. For the concrete cross-tool workflow, see [how to use Claude Code and Codex together](https://alook.ai/blog/claude-code-and-codex-same-team).

## Share a Claude Code cloud session

When your work runs in a Claude Code cloud session, follow Anthropic's [session-sharing instructions](https://code.claude.com/docs/en/claude-code-on-the-web#share-sessions). Check your account tier first; these steps apply to cloud sessions, not local CLI runs or regular Claude Chat conversations.

1. Open the cloud session you want to share and review its contents first.
2. Pick the visibility setting for your audience: Team and Enterprise accounts offer Private and Team; Pro and Max accounts offer Private and Public.
3. Send the session link to your teammate and ask them to open it from their own account to confirm access works.

Team visibility applies to members of your Claude organization. Repository-access verification defaults to on for Team and Enterprise plans and off for Pro and Max. Public links can be opened by anyone logged into claude.ai, so double-check your settings before treating a link as private to one recipient.

When someone opens your link, they see the latest saved state rather than a live-updating feed. When a teammate only needs to review what happened without running commands, send this cloud view or a CLI text export rather than terminal access.

## Export a Claude Code conversation from the CLI

In the local CLI, `/export` writes a plain-text transcript you can send to a teammate. Anthropic's [official command reference](https://code.claude.com/docs/en/commands) covers both direct file export and the interactive copy/save menu.

Inside the conversation you want to share, pass a filename:

```text
/export signup-review.txt
```

Passing a filename writes the transcript straight to disk. Entering `/export` with no filename opens a prompt to copy the conversation to your clipboard or save it to a file.

Skim the exported text first to make sure it covers the discussion your teammate needs. Then attach it in your team's usual channel with a clear ask: "Please read the discussion on the email check and let me know if it matches the product requirement."

If the transcript mentions a generated document or diff that your teammate needs to inspect, send that file along too. Depending on availability and sharing settings, Claude Code also supports [Artifacts](https://code.claude.com/docs/en/artifacts) for sharing generated pages and outputs, which is separate from exporting the chat transcript itself.

## Before sharing: access, files, and next steps

Run through a quick check before sending a session over:

- Confirm the transcript, file, or commit revision matches the exact task you are discussing.
- Check that your teammate can actually open the link and that its visibility setting matches what you want.
- Attach any diffs, logs, or docs needed to review or continue the work.
- Name the next step and who owns it.

Anthropic warns that shared cloud sessions can contain source code and credentials from private repositories, so review the conversation contents themselves alongside the link settings.

A clear handoff message stays short: "Here is the signup discussion and the current draft PR. Please review the timeout question and leave implementation paused until we agree on the behavior." Your teammate sees right away where to find the work and what needs to happen before coding resumes.

## Frequently asked questions

### Does /export include my project files?

`/export` saves the conversation as plain text. Share project files, diffs or a repository link separately when your teammate needs them.

### Who can open a shared Claude Code session?

Team visibility is for members of your Claude organization. Public links are accessible to users logged into claude.ai. Access also depends on the visibility and repository-verification settings described above.
