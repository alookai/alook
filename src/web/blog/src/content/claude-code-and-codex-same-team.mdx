**Yes, Claude Code and Codex can work on the same project.** Pick one agent to make the change and the other to review it. Keep parallel edits in separate working copies, pass a clear handoff when work changes hands, and keep final merge or release approval with a person.

You can pair them through manual handoffs, OpenAI's official Codex plugin, or a shared channel with your teammates.

You don't need to write code yourself to run this workflow, though someone still has to own repo safety, tests, and merges. If you manage the repository, jump down to the Git section for keeping parallel edits separate.

## Claude Code and Codex workflow: six steps

A two-agent workflow moves a scoped request to a verified change in six steps:

1. A person defines **one scoped task and what "done" means**.
2. One agent owns implementation; the other waits or works on a non-overlapping task.
3. If both work at once, give them **separate copies of the project** so they cannot overwrite each other.
4. The implementer sends a handoff with the work state and the requested next action.
5. The reviewer checks the diff and returns findings. The implementer fixes them, then sends the revised commit back for another review.
6. **A person approves the final merge** and any release, permission, or customer-facing change.

**Either tool can build or review.** Pick the split that fits the task and your team.

## What to include in a Claude Code and Codex handoff

- **Goal:** what this task should achieve
- **Working state:** checkout, branch, commit when available, and any uncommitted changes that matter
- **Files changed:** the intended scope of the edit
- **Decisions:** what was chosen, rejected, or left undecided
- **Checks:** tests, linters, builds, or manual checks already run
- **Open questions:** risks or blockers that still need judgment
- **Next action:** review, revise, test, or escalate to a person

![Claude Code and Codex logos with three handoff groups: goal and decisions, current state and checks, questions and next action](/blog/claude-code-and-codex-same-team/handoff-20261015.png)

*An explicit handoff keeps the next task tied to the current work.*

For a launch FAQ, a handoff might read:

```text
Goal: Prepare the launch FAQ.
Completed: Claude Code drafted answers from the approved product notes.
Decision: Keep answers under 80 words and avoid pricing claims.
Open question: Does the security answer need legal review?
Next action: Codex checks for unsupported claims and missing questions.
```

For a code change, include the branch, commit, and test status too (commit IDs and results below are illustrative):

```text
Goal: Add validation to the team-invite form.
State: branch feature/invite-validation; commit 8f31c2a; clean working tree.
Files changed: InviteForm.tsx, invite-schema.ts, invite-form.test.ts.
Decision: Validate on blur and submit; keep server errors inline.
Checks: unit tests and typecheck passed.
Open question: Should an expired invite use the same error state?
Next action: Review the diff for edge cases and test coverage.
```

### Code review workflow: fix, recheck, approve

A review doesn't stop at the first comment. Say Codex spots that an expired invite still leaves the Submit button enabled. Claude Code fixes the bug in commit `b74d2e9`, adds a regression test, and posts the new test run. Codex then checks the updated diff to confirm the fix. **A person approves that revised commit**, not the earlier one, and anything still unresolved goes back to the implementer.

*Illustrative review loop. Either tool can build or review; approval applies to the revised version.*

### Resume a session or pass a handoff

Closing a terminal doesn't always wipe your context: [Claude Code can resume saved sessions](https://code.claude.com/docs/en/common-workflows#resume-previous-conversations). Starting a fresh session is different, because the new agent won't know what you already decided or what needs to happen next.

Save your working files or make a commit first, and have the next agent check for uncommitted or untracked changes before touching anything. If the handoff note disagrees with the actual files or test output, sort out that mismatch first.

Keep in mind that shared project instructions hold standing rules, not the latest review comments. When a teammate needs the chat log itself, follow our [Claude Code session-sharing guide](/blog/share-claude-code-session) and pass the working files along separately.

## Four ways to use Claude Code and Codex together

Pick a setup based on who needs to participate and how often work changes hands. You can mix the options below, including using the plugin to call one tool from the other.

**One small or experimental task**

- **Start with:** Manual handoff
- **What it handles:** Full human control with almost no setup
- **Main limitation:** You carry every update between sessions

**Code moving between implementer and reviewer**

- **Start with:** Git branches, commits, and pull requests
- **What it handles:** Diffs, code history, and review
- **Main limitation:** Git does not assign the next owner or preserve every decision

**The whole job stays inside one product**

- **Start with:** Claude Code subagents or Codex threads
- **What it handles:** Parallel work inside one runtime
- **Main limitation:** It does not connect independent Claude Code and Codex sessions

**The same workflow repeats across both tools**

- **Start with:** A shared workspace such as Alook
- **What it handles:** Teammates work directly with each other's bots, with persistent identities and saved context
- **Main limitation:** Bots need their connected computers online; setup may be unnecessary for one-off work

[Claude Code subagents](https://docs.anthropic.com/en/docs/claude-code/sub-agents) run in separate context windows and report back to a main Claude Code session. Similarly, the [Codex app](https://openai.com/index/introducing-the-codex-app/) runs multiple agents in parallel across separate threads and isolated repo copies. Both features work well inside a single tool, but neither shares private session history with the other product.

### Use the official Codex plugin for Claude Code

To call Codex from Claude Code, install the [official Codex plugin](https://github.com/openai/codex-plugin-cc) by running these commands inside Claude Code:

```text
/plugin marketplace add openai/codex-plugin-cc
/plugin install codex@openai-codex
/reload-plugins
/codex:setup
```

The setup command checks that your local Codex install is ready and signed in. From there, pick the command that matches the job:

- `/codex:review` requests a read-only review.
- `/codex:rescue` delegates a task such as investigating or fixing a bug.
- `/codex:transfer` imports the current Claude Code session into a persistent Codex thread and returns a command to resume it (requires a Codex version with session-import support).

For a first review, diff your current branch against its base branch (replace `main` below with your project's base):

```text
/codex:review --base main --background
```

Check progress with `/codex:status`, and run `/codex:result` once it finishes to read the findings. Because `/codex:review` is read-only, you can talk through what Codex found inside Claude Code before changing any files.

Under the hood, the plugin uses your local Codex installation, sign-in, configuration, and repository checkout. **Pause other edits whenever you delegate changes in that same checkout.** The plugin doesn't spin up an isolated working copy or continuously sync both tools' private conversations.

### Git worktrees and separate checkouts for parallel edits

If you don't manage code, you can skip this section.

Stick to two rules when running agents in parallel: isolate their file edits, and always review a specific version. **Git branches separate commit history, not files on disk.** Two agents editing the same working directory will still step on each other. Give parallel tasks both separate branches and separate checkouts, using a Git worktree, a separate clone, or a container with its own checkout.

```text
implementation checkout: branch feature/payment-copy
review checkout: detached at the handed-off commit, or reviewing its PR
```

A read-only review doesn't need its own branch. If the reviewer will change files, cut a new branch from the handed-off commit, and merge only after checking dependencies, conflicts, and tests. When both agents need to touch the same file, let one finish editing before the other reviews or suggests changes.

## When one coding agent is enough

You probably don't need a cross-tool workflow when:

- one runtime and one session can finish the task;
- you are still learning either tool;
- native subagents or threads already cover the workflow;
- implementation and review rarely cross between products; or
- copying a short handoff is occasional, not recurring work.

Start with a single agent or a quick manual note. Bring in a shared workflow once you catch yourself losing track of ownership, relaying updates by hand, or repeating past decisions.

## Keep recurring Claude Code and Codex work on track

Running both apps side by side won't keep them coordinated on its own. Whenever work passes back and forth regularly, someone still has to spell out who owns the next step, what's finished, and what happens next.

**When a handoff note and the repo disagree, trust the current checkout and test results.** Git history shows committed code, while the working tree may hold newer uncommitted work. Use the handoff note for decisions, open questions, and next steps, then check the project files before continuing.

## Bring Claude Code, Codex, and Humans Together

Your team can also bring Claude Code and Codex bots into one shared project channel while keeping final decisions with a person.

Alook supports [multi-agent collaboration](https://alook.ai) by letting **teammates work directly with bots running on your own computer**. Give a Claude Code or Codex bot its own name and handle, then invite it into a project channel with people you trust. Each bot has its own inbox and joins the conversations you share with it, so teammates can ask it for help without routing every request through you.

**Each bot keeps its identity and saved context across conversations.** When work picks back up, it can check earlier messages along with its own notes on agreed responsibilities, decisions, and preferences, while marks keep unfinished requests visible. That relies on each bot recording and checking what matters; separate bots don't automatically pool all of their private memory.

### Example: two owners, two bots, one review

Here, Lin owns Scout, running Claude Code, and Priya owns Quill, running Codex. Both people and both bots belong to the project channel, and each bot uses only the repository access its owner configured.

1. Priya asks Scout directly to add invite validation. Scout checks its saved responsibilities and asks Lin whether expired invites are in scope.
2. Lin confirms the scope in the channel. Scout builds the change, posts the commit and test results, and tags Quill for review.
3. Quill catches a missed edge case. Scout fixes it and returns the new commit; Quill reviews that version and reports back to both teammates.
4. Priya checks the final result and approves the merge. Scout saves the settled requirement for future tasks and clears its mark on the request.

Lin never has to relay Priya's request or Quill's findings by hand. The bots carry the task forward and ask a person whenever a decision comes up. **Both computers and their Alook connections must stay online**, though you can close your browser and check updates from your phone.

Sharing a bot doesn't expose its owner's credentials or upload local project files behind the scenes. Channel members only see the messages and files shared in that conversation, and each bot still runs under its own configured tools and permissions.

To set this up, follow the [Codex and Claude Code tutorial](/tutorials/codex-and-claude-code) to connect your computer and both agents, or check out the [open-source repository](https://github.com/alookai/alook) to self-host.

## Claude Code and Codex FAQ

### How do you use Claude Code and Codex together?

Give each agent a scoped role, isolate concurrent edits, use Git for code changes, and send an explicit handoff when work moves between them. Keep final merge and release approval with a person.

### Can Claude Code and Codex work on the same repository?

Yes. When both edit at the same time, give each one its own checkout and branch so they don't write into the same working directory. You can isolate them with a Git worktree, a separate clone, or a container with its own repository checkout.

### Can Claude Code delegate to Codex?

Yes. OpenAI's official plugin lets Claude Code request a Codex review or delegate a task. Give it a clear goal and review target, then inspect what comes back before moving on.

### Can Claude Code and Codex talk to each other directly?

Claude Code can call Codex through the official plugin, which runs as an explicit call rather than automatic two-way sharing of every private chat. For separate agents and their owners, someone can pass updates manually, or a shared workspace can hold the messages they choose to send.

### Do I need Git or worktrees?

Not for non-code work. If both agents edit the same repository at the same time, use separate checkouts and branches to prevent them from overwriting each other's files.

### What happens when a coding-agent session closes?

You can resume a saved session, and the plugin also supports transferring a session to Codex, though neither gives every new agent all prior private history. Save the current files or commit along with a handoff note. Before picking work back up, check the checkout (including uncommitted changes) and read the key decisions.

### Does Alook replace Claude Code or Codex?

No. Alook gives your local bots persistent identities, conversations with teammates, and saved context they can use when work continues. Claude Code and Codex still run commands and edit files through their owners' configured tools. Teammates can work with those bots directly while their computers stay connected.
