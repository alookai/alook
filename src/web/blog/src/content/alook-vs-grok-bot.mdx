## Review a launch announcement with your team’s existing AI agents

Say someone on marketing is finishing a launch post. Their writing bot has a draft ready, and an engineer on the team already uses Codex on the product repository.

Marketing drops the draft into a shared Alook channel, and the engineer asks Codex to verify every feature claim against recent code changes and open PRs.

One line says a new feature is live. Codex finds the code in the repo, sees that its PR is still open and unmerged, and posts the PR link beside the draft to flag the claim.

Marketing asks Codex directly whether to cut the sentence or narrow it to what has already shipped. After double-checking with the engineer, they cut the unshipped promise and ask their writing bot to smooth out the paragraph.

**The announcement no longer promises a feature that hasn't shipped.** Marketing has the PR link backing that edit, and the engineer has signed off on the wording. Nobody treats unmerged code as live.

## Can Grok Bot run locally?

"Local" can mean local file access, self-hosting the platform, or running local model weights. If you want local inference, that comes down to which agent and model provider you run. Switching chat apps won't turn hosted inference into local inference.

### Run Grok Bot commands on your local computer

Grok Bot can [run commands on your computer](https://docs.x.ai/grok-bot/computer-and-apps#your-local-computer-is-separate) once you enable local execution, asking approval for each command by default. It can read and edit local files, so you don't need to switch to Alook just to work with a local repository.

### Can you self-host Grok Bot?

Self-hosting the platform is a separate question. Grok Bot runs on [Cursor-hosted computers](https://docs.x.ai/grok-bot/security) and doesn't support on-premises or bring-your-own-image deployments. It also has no customer-facing model picker.

### Local AI agents and local models in Alook

Alook connects the agent software you've already set up alongside your project. Which model it calls depends on how you configured that agent, so a local agent can still call a hosted model API. Our [local AI agents guide](/blog/local-ai-agents) walks through the different setups.

## Grok Bot Shared Bots and Alook group conversations

Grok Bot's [Shared Bots](https://docs.x.ai/grok-bot/shared-bots) let Cursor teammates share a single cloud Bot in group chats while keeping each person's 1:1 chats private.

Alook instead puts [each owner's bot in the discussion](/blog/introducing-alook). Marketing keeps their writing bot, engineering keeps their coding bot, and anyone in the project channel can talk to either one directly. When a teammate questions something an agent found, both that agent and its owner are right there to explain it.

We saw why this matters while updating one of our own comparison posts, where tool names were breaking into fragments inside mobile tables. One bot had drafted the copy; another caught the broken layout on mobile. Giving the tables room to scroll fixed it, and we kept the problem, the fix, and the final check together in one thread.

A finding only helps when it reaches someone who can act on it. Keeping the people and bots doing the work in the same room makes that handoff immediate.

Teammates keep their own tools and project context. And when the work calls for a new bot, an existing bot can request one for you to approve.

## Keep working with your laptop closed: Grok Bot vs Alook

Hosted compute is a real advantage when you don't want to keep a machine awake yourself. You can shut your laptop and let Grok Bot keep working in the cloud. If your team already uses its mobile app and Slack integration, that convenience is a solid reason to stay.

With Alook, the computer running a bot has to stay online. You can leave an always-on desktop or server running and check in from your phone, but if a bot runs on the laptop in your bag, it pauses whenever the laptop sleeps.
