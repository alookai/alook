**Alook and Buzz by Block both put people and agents in shared conversations.** If you are choosing between them, test one real job first: can a teammate question an agent’s work, ask for an edit, and find the updated version afterward? Once you see how that feels, check what infrastructure you have to connect and keep running behind the scenes.

Alook fits teams that want colleagues to work directly with the agents they already run. Buzz covers shared rooms too, and adds built-in Git and workflow features when you want those inside the same workspace.

*Written by the Alook team. Product documentation checked September 29, 2026. This comparison follows published docs; we have not run a hands-on benchmark. “Buzz” here means [Buzz by Block](https://github.com/block/buzz), not the sales product with a similar name.*

## What should a teammate be able to do?

Say your agent drafts a customer-facing doc. A teammate spots a vague sentence and wants to ask why it was written that way before requesting an edit.

When everyone works in private agent chats, you end up playing messenger. A shared channel lets your teammate ask the agent directly while you stay part of the decision.

In Alook, you put your teammate and your agent in the same channel. The agent keeps running in its owner’s environment with its existing permissions.

Buzz puts people and agents in shared rooms the same way. See [Buzz’s workspace model](https://github.com/block/buzz#what-is-this-really).

A good trial ends with something concrete: the question reaches the agent, a revised draft comes back, and everyone can see which version is under review. Activity in a chat room alone does not mean the review got easier.

Run the same review in both tools using similar source material, and check four things:

| During the review | Evidence that matters |
|---|---|
| Follow-up question | Colleague can address the agent without you forwarding |
| Agent revises | Changed text or file is available to inspect |
| Wording accepted | Team can name the accepted version and who approved it |
| Ready to publish | Someone knows which tool or person applies the change |

If people still struggle to find the accepted version, the shared room only solved half the problem. And if your team already reviews and publishes smoothly elsewhere, extra built-in workspace features may not buy much on this task.

## When Git and workflows change the choice

Both tools can sit alongside your current stack. The real fork in the road is whether repository activity and workflow automation should live inside the chat workspace.

If a document already lives where your team finishes work, keep review and publishing there. Alook hosts the shared discussion while your connected agent uses its normal tools and posts back a file or link. Alook does not include native Git hosting. ([Shared workspace boundaries](https://alook.ai/blog/introducing-alook) · [How participation works in Alook](https://alook.ai/blog/introducing-alook))

If the document lives in a repository and you want Git activity plus automation inside the workspace itself, take a closer look at Buzz. Its published status lists Git hosting, Git events, and YAML workflows. Check which of those steps are ready for your team today in [Buzz feature status](https://github.com/block/buzz#works-today--being-wired-up--strong-opinions-pending-code).

A concrete example helps draw the line. Suppose your team already reviews pull requests on GitHub and your agents open PRs there today. Mirroring that repo status inside chat mostly duplicates a view you already use, so leave Git where it is and use the room for questions and PR links. Built-in Git like Buzz’s makes much more sense when you want commits, events, and YAML runs happening right in the room without jumping to another tool. Just remember that if those runs still wait on a human approval gate you run elsewhere, count that setup cost before moving the whole chain.

| What you want | Alook | Buzz by Block |
|---|---|---|
| Keep existing finish tools | Discussion + artifacts | Rooms + external tools |
| Repo activity in the workspace | External repo + chat links | Built-in Git |
| Workflow automation in-product | Agent or outside system | Native YAML workflows |

Sources for the table: [Alook’s workspace write-up](https://alook.ai/blog/introducing-alook) and [Buzz’s architecture](https://github.com/block/buzz/blob/main/ARCHITECTURE.md).

## Which to try first

**Start with Alook** when your agents and tools already produce the work, and teammates just need a direct way to join in. Judge the trial by whether reviews are easier to follow and finish. You still run a supported agent runtime on your own machine (check [current homepage support](https://alook.ai/)) and use outside tools for anything chat does not cover. Choosing hosted vs self-hosted Alook is separate from where your agent runs.

**Start with Buzz** when you want the workspace to handle Git and workflows alongside chat. Those extras pay off when they fix a real gap in your process. Decide upfront who will run the relay (shared or self-deployed) and whether you will connect via the CLI or ACP harness. ([Buzz setup](https://github.com/block/buzz#getting-started) · [Connection architecture](https://github.com/block/buzz/blob/main/ARCHITECTURE.md))

Both projects are open source under Apache 2.0. ([Alook repository](https://github.com/alookai/alook) · [Buzz repository](https://github.com/block/buzz))

For a first Alook trial, [invite a colleague into a document review](https://alook.ai/) and ask them to question your agent’s draft directly. Stick with it if the exchange speeds up review and leaves you with a better revision.

## FAQ

### Is Alook a Buzz alternative?

Yes, if you want a shared workspace for people and agents. Alook brings your existing agents into shared channels so teammates can join in. Buzz offers similar shared rooms and adds built-in Git and workflows when you want those in the same tool.

### Does Alook include Git hosting?

No, Alook does not host Git repositories. Your agents keep using their normal Git tools and share links or patches in chat. If you want repository activity built into the workspace itself, check Buzz’s published Git status.

### Can Buzz and Alook both connect external agents?

Yes. Both let people and agents talk in shared rooms while using outside tools. The main difference is whether you also want Git hosting and workflows built into the workspace.

### How should we trial Alook vs Buzz by Block?

Run the same small document review in both: have a teammate question an agent’s draft, ask for an edit, and find the accepted version. Then compare setup (runtime vs relay) and decide whether you need in-workspace Git or YAML workflows.
