## Claude Code vs Codex: Desktop, CLI, IDE, and Cloud

If you're new to terminal tools, start with the Code tab in Claude Desktop or Codex inside the ChatGPT desktop app. If you already live in a terminal or code editor, use the CLI or IDE extension instead.

Both desktop apps keep the chat and file changes side by side, while the CLIs run in your terminal and the extensions sit inside your editor. Either way, you'll spend most of your review reading a **diff**: the added and removed lines in a proposed patch.

## Permissions and Sandboxing in Claude Code and Codex

Will either agent edit files without asking? In Claude Code, Manual mode prompts you before file edits and most commands unless a saved rule already allows them. In Codex, "Ask for approval" still lets the agent edit files and run commands inside your workspace, prompting only when it tries to cross that boundary.

Starting in [Claude Code v2.1.283](https://code.claude.com/docs/en/permission-modes), interactive terminal and VS Code sessions start in auto mode, where another AI model reviews actions in the background. Its default checks target destructive commands like force pushes and `git reset --hard` that could wipe out work.

Codex's local workspace-write sandbox allows edits and commands inside the project, keeps command network access off by default, and mounts `.git` as read-only. That protects your Git metadata, though source files in the working tree can still be modified or deleted. Hosted search and connected tools use separate network controls.

| What you want to control | Claude Code | Codex |
|---|---|---|
| Who approves actions | Manual asks before file edits and most commands, except actions already allowed by a saved rule. Auto uses an AI reviewer. | Ask for approval still permits edits and commands inside the workspace; it asks before crossing that boundary. |
| Discuss a change before source edits | Plan mode proposes changes before source editing. | Read-only mode lets you discuss and inspect the project before granting write access. |
| Where the setting is | The permission mode selector; `/permissions` in the CLI lists rules. | The control below the prompt, or `/permissions` in the CLI. |

Saved settings or organization policies can override these starting modes. [Codex's launch rules](https://learn.chatgpt.com/docs/agent-approvals-security) call its workspace-write preset Auto and recommend it for Git folders (with read-only for non-Git folders), while the desktop app labels that same workspace boundary Ask for approval. Keep the naming difference straight: Codex's Auto preset sets file access and approval boundaries, whereas Claude's auto mode brings in an AI reviewer.

In short, a sandbox restricts which files and network resources a command can touch, while approval controls whether the action runs at all.

When a test command fails, check the error for a missing dependency or blocked network call before opening up broader permissions. Keep in mind too that running commands on your machine doesn't make the model local: both apps still send code context to hosted models.

## Compare Claude Code and Codex on the Same Coding Task

Running a small validation fix tells you more about working with an agent than asking it to build an entire app. You can verify the behavior right away, and the diff stays small enough to discuss line by line. Whichever tool you already have installed is enough to start.

Take a contact form that accepts a name made entirely of spaces. Your fix should reject blank spaces while keeping valid names working. No form in your project? Filtering completed to-do items out of an active list gives you an equally clear change to verify.

Before starting, make sure you can tell the agent's edits apart from your own. Run `git status` and `git diff`, commit your own intended changes, and leave anyone else's unfinished files out of that commit so earlier edits don't get mixed into the agent's patch.

For the form fix, a short prompt is plenty:

> Find the name validation for this form. Reject names that contain only spaces, keep valid names working, and add or update the relevant test. Use the project's existing tools. Explain the files you expect to change before editing. Show the diff and the test command and result when finished. Do not commit or publish.

The real evaluation starts once the patch comes back. Does its validation reject whitespace-only names cleanly, or does it accidentally block valid names too? Ask the agent to walk through that condition so you have something concrete to push on. If you'd rather make the edit yourself, ask for a proposed approach and explanation before any files change.

Passing tests only help if they actually check the behavior you wanted. We ask for the test before the fix so we can watch it fail on the old code and pass after the change. Then open the page and submit a spaces-only name followed by a real name. Manual checks regularly catch UI quirks an automated test missed.

Even if you don't read code, you can run both test submissions in the desktop workflow (or check off a to-do item and confirm it leaves the active list).

After one round, you have concrete signals to compare: how much explaining and correcting the patch took, how long each revision ran, and how much plan allowance it used. Commit only the intended files you've reviewed. A fast first draft loses its shine if you spend the rest of the session fighting to restore a basic requirement.

**Optional: compare both tools.** Spin up separate clones or Git worktrees at the same starting commit and hand Claude Code and Codex the exact same prompt so their edits can't collide. Running identical tasks makes wait times and correction rounds easy to compare, though you don't need to buy both tools just to run this exercise.

### Missing Requirements Leave the Agent to Decide

In a published 48-run comparison, one book-site ticket asked for a year of asset caching without spelling out exact HTTP response headers. Five of the six runs picked headers that didn't match the researcher's expectations. Whenever we see a miss like that, we check what the prompt left unspoken before blaming the agent.

On the seven clearer tickets, the researcher had a preparation agent write explicit specs from reference changes he had already finished, covering every behavior checked by his grading tests without exposing the tests themselves. Given clear requirements, all 42 runs passed (three runs per tool on each ticket).

Tests themselves can share a blind spot too. We once watched an automated reviewer catch a wrong column heading in a patch where every check had passed, because the test expected that same wrong wording. Comparing the patch back against the original request caught what the test suite missed.

### What Happens When Claude Code or Codex Hits a Usage Limit?

When either tool hits a usage cap, check your remaining allowance and reset time first. If the reset window is close, we wait it out. When a task can't wait, weigh paying for extra usage against switching tools with a short handoff note covering modified files and remaining steps.

Pro Codex plans currently carry no five-hour cap, whereas Plus enforces both five-hour and weekly limits. Claude Pro and Max enforce both windows too; verified Ultra accounts drop the five-hour cap while keeping a weekly allowance. On Max and Ultra, Fable counts toward that weekly allowance and can use up to half of it.

To check Codex quota, open the [usage dashboard](https://chatgpt.com/codex/settings/usage), run `/status` in the CLI to view remaining limits alongside session details, or run `/usage` to see token activity and any available reset option. In Claude Code, `/usage` shows your plan usage. Starting a fresh chat or switching models won't refill a shared plan allowance.

## Should You Choose Claude Code, Codex, or Both?

Starting from scratch with $20 a month and comfortable reviewing small diffs? Our first pick is ChatGPT Plus with Codex. Its diff pane, inline comments, and built-in Git controls make choosing which changes to keep straightforward, even though the wait between small edits still bugs us.

Already paying for Claude Pro? Start with Claude Code instead. It's also the better pick if you want explicit sign-off on every file edit: Claude's Manual mode asks first, whereas Codex's Ask for approval mode edits files inside the workspace freely and only prompts at the workspace boundary. And if your account includes the free Codex desktop offer, try a small task there before spending $20.

Reach for Claude Code with Opus 5.5 when you want the top scorer in the four-configuration chart above and can live with its longer runtime on your tasks.

Paying for both makes sense once you want a second agent reviewing patches independently, or when one tool supports an integration your main agent can't use.

### MCP, Hooks, and Skills: What Changes When You Switch?

MCP connects agents to external tools and data, hooks run scripts on events like tool calls, and skills package reusable task instructions. You don't need to migrate any of them just to run the small validation exercise above.

Before moving an established project, test the integrations you rely on daily. In earlier releases, we saw Claude Code drop details from the middle of long MCP error responses and watched Codex miss a newly added server tool. Porting hooks and skills usually takes adjustments and another round of testing too.

### AGENTS.md vs CLAUDE.md: Which Instructions Load?

In repos that already define agent rules, Codex loads [AGENTS.md project instructions](https://learn.chatgpt.com/docs/agent-configuration/agents-md), letting files closer to the working directory override parent directories. Under [Claude Code's default rules](https://code.claude.com/docs/en/memory#when-claude-code-reads-agents-md), any `CLAUDE.md`, `.claude/CLAUDE.md`, or `CLAUDE.local.md` in the working directory or above takes precedence over `AGENTS.md`. When none of those Claude files exist, Claude Code v2.1.277 or later reads `AGENTS.md` directly unless its bundled `AGENTS.md` reader has been disabled.

On current Claude Code versions, run `/memory` to verify what actually loaded. If an existing `CLAUDE.md` shadows `AGENTS.md`, import `@AGENTS.md` inside that `CLAUDE.md` or update Project instructions to load both. Dropping an instruction file into the repo doesn't prove both agents read it.

## Claude Code and Codex FAQ

### Do Claude Code and Codex Require an API Key?

No. Both tools work without an API key: Codex signs in with a ChatGPT account, and Claude Code signs in with a Claude account on an eligible plan. API-key access is also available if you want separate pay-as-you-go billing and limits.

### Do Separate Git Worktrees Share Uncommitted Changes?

No, separate Git worktrees don't share uncommitted files automatically. Pass a commit to check out or a patch to apply so both bots inspect the exact same version.
