I analyzed 3,283 X posts on Claude Code, Codex, Cursor, Grok Bot, Grok Build, Antigravity, and OpenCode. 757 of them were about a real job. Here is who to try first.

![Post counts and positive versus negative feedback for seven agents, ordered by increasing negative share](/blog/claude-code-codex-cursor-grok-which-to-choose/agent-feedback.png)

[Open full-size chart](/blog/claude-code-codex-cursor-grok-which-to-choose/agent-feedback.png).[^feedback]

- Already have a repo: Claude Code or Cursor.
- The machine or old software is broken: Codex.
- A small game or personal tool this week: Grok Build.
- Mail, files, reminders: Grok Bot.
- A page that has to look like the mock: Antigravity.
- You pick the model yourself: OpenCode.

Skip Codex for visual design. Skip Antigravity for maintaining an existing app. Do not leave Grok Bot in charge of a long project. Do not treat a Grok Build first version as finished.

The rest of this piece is the catch for each harness.[^method]

## Grok Bot: give it the inbox, not the project

The jobs that work have a done state you can see. Clearing email and unsubscribing. Moving Notion pages. Delegating a site fix to Cursor and asking whether the PR landed.[^bot]

A paper still fell short after three weeks. Across sessions it forgets what it already did, waits to be poked, and misses a long brief. Use it as a clerk. Do not leave it as the owner of a project.

## Cursor: the bug in this repo, not the rest of the tree

Point it at a recording of a broken UI, or turn on Debug mode, and stay inside a project that already exists. That is the useful shape: a specific fault, code in front of you, another pass if the first patch is wrong.[^cursor]

A navigation fix rewrote authentication. Another patch overwrote files already staged for commit. The bug can look fixed while the rest of the tree moved. Read the diff even when the change looks small.

## Claude Code: it will take the whole job, including extra files

This is the one people hand a real implementation. An old PHP blog. Twenty sites to migrate. A design that has to become a site. It keeps going on work that already has requirements and a repo.[^claude]

It also keeps going past the request. A small fix becomes a rewrite across files. Tests go green and registration still errors. Treat "done" as a claim. Click the signup flow yourself.

## Grok Build: ship the first playable version

The posts that like it are about things already in use: a tower-defense game on a phone, a lithophane cut for a specific printer, tools a family is already opening. Speed to a version you can try is the point.[^build]

Then the second week. A plugin that appeared in one pass, then never got its bugs fixed. A store preview that looks finished while product data is still stuck. A first version is not a finish. There are large-project wins in this sample; they do not cancel the stall after v1.

## Antigravity: make the thing you can show

A 3D shoe site. Scroll animations from reference stills. If the job is "can I see this idea," start here.[^antigravity]

If the job is "this existing app is broken," start somewhere else. Failed repairs. Tests rewritten to match the bug. "Complete" without looking. A pretty page is not evidence it can keep a codebase alive.

## OpenCode: you own the stack, so you own the stall

People pick it to combine their own models, interfaces, and local setup. Recovering a lost production container is the kind of win that shows up. Scripts and environment repairs show up too.[^opencode]

The cost is operational. Failed tool calls. Reading the same file on a loop. A session that finishes the plan and then spins. When it sticks, you are debugging the model and the glue, not only the app. Switch models, fix the connection, or cut the task up.

## Codex: repair what used to run

Audio buffers. Device wiring. Thirty-year-old assembly. Old games that should boot again. Concrete breakage in an environment you already have, or a repetitive job you want scripted.[^codex]

Do not start here for how it looks. Website taste, Blender characters, PowerPoint and PDF layout all get negative notes. One successful old-program repair also does not mean the next port will finish. A Roblox migration sat in fixes for a week.
