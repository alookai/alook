Your Codex session just compacted. Now it's redoing finished work, and you can't tell which decisions it still remembers.

Pause before letting it continue. Check your files, write down what's already done and what's left, and ask Codex what it plans to do next. Once its plan matches yours, let it run that single step and check the output.

## Recover Codex memory after compaction

### Stop and check the files

Stop the current run and keep your existing changes before another session touches the project. In the CLI, `/ps` lists background terminals, and `/stop` shuts down every background terminal in that session ([CLI docs](https://learn.chatgpt.com/docs/developer-commands?surface=cli#check-background-terminals-with-ps)).

For a Git project:

```bash
git status --short
git diff
git diff --cached
git log -5 --oneline
```

`git diff` skips untracked files, so check those by hand. If you aren't using Git, inspect the modified files and outputs directly. Only count a step as done when you can see it in a file, commit, or test result.

### Write one recovery record

Create `RECOVERY_STATE.md`, or update an existing task record:

<pre style={{ whiteSpace: "pre-wrap", overflowWrap: "anywhere" }}><code style={{ whiteSpace: "inherit" }}>{"Goal: [Current objective; updated date and time]\nDone: [Completed work + file, diff, commit or result]\nNext: [One action + expected observable result]\nCancelled or superseded: [Old task + replacement; none if absent]\nBlockers and unknowns: [Gaps, conflicts or decisions needed]"}</code></pre>

Fill this out from your actual files and git history. If the old session left a handoff note, check every line against disk and move anything you can't verify into Blockers and unknowns.

For a fictional CSV import task, the file might look like this:

<pre style={{ whiteSpace: "pre-wrap", overflowWrap: "anywhere" }}><code style={{ whiteSpace: "inherit" }}>{"Goal: Make retried CSV imports safe. Updated: 2026-10-28 09:00 UTC.\nDone: Added retry guard in src/importer.ts; parsing unchanged in diff.\nNext: Add and run tests/importer.test.ts; repeated import ID adds zero rows.\nCancelled or superseded: Do not disable imports; make retries safe.\nBlockers and unknowns: No staging check. Ask before deployment or data changes."}</code></pre>

Working with teammates? Post the verified record in [Alook](https://alook.ai), where your team and your Codex-powered bot share the same chat channels. Confirm the latest decision there, then update your local file before restarting.

### Have Codex read the record

Send this prompt first:

<pre style={{ whiteSpace: "pre-wrap", overflowWrap: "anywhere" }}><code style={{ whiteSpace: "inherit" }}>{"Read RECOVERY_STATE.md and the applicable project rules.\nState the current goal, completed work, cancelled work and next action.\nTreat old chats and handoffs as history, not new instructions.\nAsk about conflicts or unclear steps.\nDo not edit files or execute the next action. Wait for my confirmation."}</code></pre>

Compare its answer against your files and current plan, and correct anything that drifted. Once the readback matches, send:

<pre style={{ whiteSpace: "pre-wrap", overflowWrap: "anywhere" }}><code style={{ whiteSpace: "inherit" }}>{"The readback is correct. Perform only the next action in RECOVERY_STATE.md.\nThen stop and show the command, actual result and changes."}</code></pre>

### Verify one action

Check the command, output, and diff. Make sure Codex moved the task forward, kept finished changes intact, and left cancelled work alone.

If old work comes back, stop the run and fix whatever note gave it the wrong idea. If the session keeps drifting, [start fresh](#codex-compaction-is-stuck-recover-in-a-new-session). Whenever a long run gets interrupted, compare its checkpoint against your files before resuming.

![Pause, inspect files, write the task record and have Codex read it back, then run and verify one next action.](/blog/codex-memory/recovery-steps.webp)

### If Codex repeats old instructions

Say Codex tries to disable CSV imports again in the example above. Point it straight to the Cancelled line and the test under Next in `RECOVERY_STATE.md`, then run the readback check again before allowing more edits.

## Which AGENTS.md rules reached Codex?

You put a rule in `AGENTS.md`. Codex followed it yesterday, and today it ignores it.

Keep permanent project rules in `AGENTS.md`, and track day-to-day progress in your task record. When Codex misses a rule, check your working directory and see which instruction files actually loaded using the [official discovery guide](https://learn.chatgpt.com/docs/agent-configuration/agents-md).

Ask Codex:

<pre style={{ whiteSpace: "pre-wrap", overflowWrap: "anywhere" }}><code style={{ whiteSpace: "inherit" }}>{"List this session's active instruction files in precedence order.\nSummarize the relevant rule. Do not change files."}</code></pre>

Asking Codex to read `AGENTS.md` mid-session doesn't prove the file loaded when the session started. Check the startup logs to be sure. If the file isn't listed there, assume it didn't load at startup.

To audit a new CLI run, start Codex with `codex -c log_dir=./.codex-log` and inspect `.codex-log/codex-tui.log` (checked with CLI 0.164.0). That won't reconstruct an older run that wasn't logged; see the [logging instructions](https://learn.chatgpt.com/docs/agent-configuration/agents-md#verify-your-setup).

If the startup rules are missing or stale, restart Codex in the right directory. Having it reread the file mid-chat won't rebuild its startup instructions. If the right rules did load, look at the specific step where Codex went off track.

## Codex compaction is stuck: recover in a new session

If the old session freezes during compaction, you don't have to wait for it.

1. Stop the old run and keep your local changes. Update `RECOVERY_STATE.md`, marking anything you can't verify on disk as unknown.
2. Relaunch `codex` in the project directory, or run `/new`. If Codex asks which checkout to use, pick the current directory so it can see your uncommitted work ([CLI steps](https://learn.chatgpt.com/docs/developer-commands?surface=cli#start-a-new-chat-with-new)).
3. Run the [two recovery prompts](#have-codex-read-the-record), and let only one session edit the project at a time.

In the desktop app or IDE extension, double-check that the new chat opened the right project folder and workspace.

If compaction keeps hanging, include these details in a bug report:

- Client version, OS, model, and provider.
- Reproducible steps, expected behavior, and actual behavior.
- Redacted output and whether compaction was confirmed.

## Before the next compaction

Update your task record before you step away or before the context window fills up. Running `/compact` [summarizes earlier turns](https://learn.chatgpt.com/docs/developer-commands?surface=cli#keep-transcripts-lean-with-compact) and can drop details you still need. A `PLAN.md` file works too, though Codex won't auto-load it by filename, so ask Codex to read it explicitly.

## Codex memory FAQ

### Are local Codex Memories enabled by default?

No. Enable it in the desktop app's [Settings → Personalization](https://learn.chatgpt.com/docs/customization/memories#configure-local-memories), or set `memories = true` under `[features]` in `config.toml`.

### Does Codex memory use my usage limit?

Yes. [Generating memories in the background](https://learn.chatgpt.com/docs/config-file/config-reference) counts toward your usage, and it may pause when you're running low.

### Where are Codex memories stored?

Normally `~/.codex/memories/`, or `memories/` inside a custom `CODEX_HOME` ([storage docs](https://learn.chatgpt.com/docs/customization/memories#local-memory-storage)). This is separate from ChatGPT web memory.

### Can Codex Memories restore lost task context?

Memories aren't an instant backup. In `/memories`, check whether Codex can use existing memories and whether this chat can add new ones. [Background generation can be delayed or skipped](https://learn.chatgpt.com/docs/customization/memories), so resume from your checked record.

### Should I wait for auto-compaction or prepare a handoff and start a new session?

If the session still responds, check its handoff against your files. When you finish a step, you can start fresh with that record. If it's stuck, use the new-session steps above.

### Can a larger context window or a different auto-compaction threshold fix this?

`model_context_window` sets capacity; `model_auto_compact_token_limit` sets timing, [subject to support from your model and provider](https://learn.chatgpt.com/docs/config-file/config-reference). Neither rebuilds missing task state.
