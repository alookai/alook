## What is a local AI agent?

An AI agent combines a model with a loop that can inspect state, act through tools, and evaluate what happened. A coding agent might edit a repository and run tests. A productivity agent might read selected documents and prepare a summary.

Claude Code, for example, runs locally but [sends data over the network to interact with the LLM](https://code.claude.com/docs/en/data-usage). Its standard model paths are hosted. The process and files can be local while the model request goes elsewhere.

## “Local” can describe three different layers

The model, tool execution, and shared workspace can each run in a different place.

### Local model and local runtime

Both inference and the agent loop run on hardware you control. Local inference adds hardware requirements: model size, context length, and simultaneous requests all affect the memory needed. A model that fits for a short chat may leave less room for a long agent conversation.

### Local runtime with a hosted model

Here, the agent process runs beside your files while inference happens through an API. Prompts and sent context leave the machine. This can suit someone who wants a hosted model to work with local files without also maintaining local inference.

Our [OpenCode and Claude Code comparison](/blog/opencode-vs-claude-code) covers model choice and what changes when you switch between the two runtimes.

### Local runtime connected to a shared room

The agent runs on its owner’s machine while a shared service coordinates messages and room state. A teammate can ask for a result there; the runtime still uses the file and tool permissions its owner configured.

## What happened in our local file test

On November 17, 2026, we ran OpenCode 1.19.5 with Ollama 0.40.16 on a 16GB M1 Pro Mac. The downloaded `qwen3.5:4b` model used Ollama’s MLX runner. We set a 65,536-token context window and limited reads to the test directory.

We made two short workshop notes. One gave the date as November 26 and the room capacity as 24; the other said November 27 and 18. Both named the same invitation owner and a 14:00 start. We asked the agent to read the files, identify the conflicts, and leave the final decision to us. The file contents were not attached to the prompt.

The first attempt requested paths at the filesystem root, outside the allowed directory. Full `/tmp/...` paths were refused too. On this Mac, `/tmp` points to `/private/tmp`. For the next attempt, we used that canonical path and changed the rule to allow only the test folder.

Before the successful file comparison and its offline repeat, we switched off thinking and removed automatically loaded external skills. Two completed read entries then appeared in the tool record, each containing the actual file. The answer found both conflicts and named the invitation owner. The shared 14:00 start was missing from its agreement summary.

We then blocked external network access for both OpenCode and Ollama, leaving loopback available for their local connection. Both files still opened with the same prompt. It missed the 14:00 start again.

A separate request to fetch `https://example.com` failed with a transport error under the network restriction. The model went on to suggest the page normally needed authentication. The tool result didn’t establish that, and the page returned 200 without credentials outside the restriction. Reading the tool record let us separate the failed connection from the explanation the model added.

This setup could compare local documents without an external connection after the model and runtime were downloaded. A task that needs a current webpage has another dependency. A small file task is a useful first check because you can inspect both the tool calls and every claim in the answer.

## How local AI agents fit into a team

When someone else needs to review the result, share the relevant artifact and the question you want checked. For our notes, that would mean passing on the two conflicting dates and capacities, rather than telling a reviewer that the summary was finished. Credentials and unrelated private files can stay outside that handoff.

## Local AI agent FAQs

### Do local AI agents work offline?

A local model and runtime can complete tasks whose inputs and tools are available on the machine. Our two-file task continued with external networking blocked; the web fetch did not. Downloading the model and preparing the runtime were separate, online steps.

### Does a local agent require a local LLM?

No. Claude Code’s standard setup is one example of a local runtime using hosted inference. A local LLM is a model choice; it is separate from where file reads and commands run.

### Are local AI agents private?

Local inference keeps the model request on your hardware. Tools, logs, telemetry, and shared messages can still send data elsewhere. The three-layer distinction helps you trace the particular task rather than assign one privacy label to the whole product.

### Can teammates use the same local agent?

A shared conversation lets teammates request work and review what an agent returns. It doesn’t expand the runtime’s local permissions. Keep the folder and tool scope with the owner who runs it.
