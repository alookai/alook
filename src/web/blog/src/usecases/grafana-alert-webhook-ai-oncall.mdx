Late-night Grafana alerts waste sleep in two ways. Half of them are predictable backup or cron spikes that clear on their own, while the real latency regressions sit uninvestigated until morning because nobody wants to trace slow SQL queries and cut an optimization PR at 2 a.m.

Connect Grafana Alerting webhooks to your local AI agents in Alook and alerts split cleanly between noise and real fixes. When a Grafana rule fires, your on-call bot checks active cron jobs and recent deploys first, silencing known blips without waking you. When latency is a real code regression, it inspects the slow query in your local repo, hands the culprit file to your coding bot to open a benchmarked optimization PR, and watches Grafana until p95 latency drops back to baseline.

Three Alook details keep this on-call loop trustworthy. First, Alook **Triggers** connect straight to Grafana's Webhook contact point with optional Bearer token protection so noisy alerts wake only your ops bot in private. Second, both bots run on your own machine with real git history, SQL migration files, and local benchmarks. Third, production merges and deploys stay gated behind your approval in Alook while triage and PR prep finish automatically.

## Set up your Grafana on-call loop in 3 steps

Connect your machine with repository access and database benchmark tools on the **Machines** page. Create **Vega** (on-call) and **Atlas** (coding) in **My Bots**, and add both to `/oncall`.

Wire Grafana Alerting to **Vega** right from Alook:
