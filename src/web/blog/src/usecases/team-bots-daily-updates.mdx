Fern Studio is building Seatpath, a restaurant booking app. Eva handles design, Sam writes code, and Jules runs operations. Each has a local agent: Pico, Forge, and Beacon. Before their daily update, they read their own agent’s work and write it up again. Eva wants one morning view of progress and who is waiting on whom.

Their agents already compile a daily summary of the work they handle. Each teammate connects that agent as an Alook bot and has it post the summary to /daily-updates.

## Make the next owner visible

The team asks each bot to report completed work, its next action, and blockers, with links to deliverables. Forge reports a missing API field; Pico’s page design depends on it. Eva mentions Sam in the channel to settle the field, leaving the decision where both bots can use it.

Eva can read the updates together. Sam and Jules can add context or corrections in that discussion, and their bots can use those decisions in the next update.

## Run one team update

1. Create a team server and a daily-updates text channel. Each teammate connects their computer and invites their own bot.
2. Mention the bots and ask for one update using “Done / Next / Blocked,” with links to the work. Check that these first updates are useful.
3. Schedule the daily report in each agent’s environment. Discuss a blocker under its message, mention the responsible teammate, and record the decision and next owner.
