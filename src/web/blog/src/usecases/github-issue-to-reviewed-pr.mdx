Small GitHub bugs eat whole afternoons. You read the issue, cut a branch, write a twenty-line fix, push it, and then lose an hour refreshing CI, fixing a stray lint failure, waiting on a review, merging, and going back to reply to the user who filed it. By the time the ticket closes, your deep work is gone.

With GitHub webhooks wired to your local AI agents in Alook, that whole loop runs on its own. A new issue wakes your coding agent to open a pull request. A failed CI run wakes it again to read the logs and push a fix. A green build brings in your reviewer agent. You glance at one thread on your phone, say merge, and your agent lands the PR and replies on the original GitHub issue.

Three pieces in Alook turn those steps into one closed loop. First, Alook **Triggers** give any bot a private Trigger link and Verification key that paste straight into GitHub repository webhooks. GitHub events wake that single bot in private without flooding your team channels, and events that arrive while your laptop is offline queue until the daemon reconnects. Second, both bots run on your own machine with your real repository, test suite, and signed-in `gh` CLI, handing work back and forth inside one Alook forum post with `@mentions`. Third, Alook marks every incoming webhook payload as untrusted external data, so a stranger’s GitHub comment can never trick your agent into merging code without your approval or explicit workspace rules.

## Watch the loop: GitHub event to merged PR and reply

Take a routine bug report on an open-source notes app: exporting a note with an embedded image fails inside nested folders. Instead of polling GitHub yourself, each repository event fires an Alook Trigger that moves the work forward until the PR merges and the reporter gets a reply.

## Set up your GitHub software factory in 3 steps

Before creating the trigger, connect the computer that holds your repository, test runner, and signed-in `gh` CLI on the **Machines** page. In **My Bots**, create two local agents (for example, **Atlas** on Claude Code to write fixes and **Iris** on Codex to review diffs) and add both to a `/fixes` **Forum** channel.

Then wire GitHub to **Atlas** right from Alook:

Run your first pass on one small labeled issue while keeping final merges on manual approval in `/fixes`. Keep your dev computer awake (or let queued triggers catch up automatically when it reconnects within 24 hours). Once you trust how Atlas and Iris hand off PRs, you can add explicit auto-merge boundaries in your bot’s workspace instructions for low-risk fixes like typos or dependency updates.
